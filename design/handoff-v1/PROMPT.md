# PokeSix — Claude Code 구현 프롬프트

> 이 파일을 Claude Code에 그대로 붙여 넣거나, 패키지 폴더를 저장소 루트에 `design-handoff/`로 두고
> "design-handoff/PROMPT.md를 읽고 시작해"라고 지시하세요.

---

## 너의 역할과 목표

너는 **PokeSix** 데스크톱 앱의 UI를 C++17 · Qt 6 Widgets로 구현한다.
디자인은 확정되었고, 이 패키지(`design-handoff/`)에 화면 캡처, 디자인 시트, 화면 정의서, 설계서, 아이콘 원본이 모두 들어 있다.
목표는 **캡처 이미지와 나란히 놓았을 때 같은 화면으로 보이는 앱**을, 유지보수 가능한 구조로 만드는 것이다.

## 1. 현황

| 항목 | 상태 |
|---|---|
| 제품 정의 | 포켓몬 시리즈 플레이 보조 도구. 세대별 도감 · 아이템 조회, 6마리 파티(SixSquad) 구성과 실시간 타입 분석. 사용자는 시리즈를 세대별로 정주행하는 성인 플레이어 |
| 기술 스택 | C++ / Qt 6 (Widgets), 크로스플랫폼 (macOS · Windows · Linux) |
| 디자인 | **완료.** 화면 5종(1440×900) + 좁은 창 2종(1024×768) + 기초 · 아이덴티티 · 컴포넌트 보드. `images/screens/`가 기준 이미지 |
| 디자인 원본 | `design/source/*.dc.html` — 모든 px 값 · 색 · 문구의 정답. 이미지와 수치가 다르면 **원본의 수치가 우선** |
| 코드베이스 | **확인 안 됨.** 이 패키지를 만든 쪽은 저장소를 보지 못했다. 먼저 저장소를 살펴보고(§4-0) 현재 상태를 보고할 것 |
| 데이터 원본 | **미정.** 도감 · 기술 · 아이템 데이터를 어디서 가져올지(라이선스 포함)는 사용자 결정 사항. 그 전까지는 시드 데이터로 개발 |
| 이미지 에셋 | 포켓몬 스프라이트 · 공식 아트는 **넣지 않는다.** 디자인은 `[스프라이트]` 자리표시자로 되어 있다 |

## 2. 디자인 방향 (요약 — 자세한 값은 `docs/01_DESIGN_SHEET.md`)

- **밝은 테마가 기본.** 종이색 바탕(`#F3EFE6`) 위 흰 창. 다크 테마는 설정에서 선택하는 옵션.
- **주색은 빨강(`#D8322B`)과 하양.** 앱 상단 막대는 빨강, 본문은 하양 — 위 빨강 · 아래 하양 구성. 파랑 · 초록 · 노랑이 보조색으로 알록달록하게.
- **너무 현대적이지 않게.** 먹색(`#2A2A33`) 2px 외곽선, 아래로 떨어지는 단단한 그림자(블러 없음), 컬러 머리를 단 각진 "창", 옛 게임 메뉴 같은 노란 선택 칸 + ▶ 커서. 제목은 도현, 라틴 로고는 Silkscreen(도트 글꼴), 본문은 나눔고딕.
- **정보 밀도가 높은 도구.** 장식보다 판독성. 모든 색 신호에는 숫자나 글자가 함께 있다(색각 이상 대응).
- **마크 "여섯 칸".** 육각을 이루는 삼각 6칸, 빨강 · 파랑 · 초록 3칸 + 하양 3칸. 포켓볼 모양(원 + 띠 + 버튼)은 쓰지 않는다 — 공식 디자인이라서.

## 3. 읽는 순서

1. `images/screens/*.png` — 먼저 전부 본다. 이게 최종 결과물의 모습이다.
2. `docs/01_DESIGN_SHEET.md` — 토큰 · 타이포 · 컴포넌트 규격
3. `docs/02_SCREEN_SPEC.md` — 화면 정의서 (화면별 구성 요소 · 상태 · 동작 · 반응형)
4. `docs/03_ARCHITECTURE.md` + `images/diagrams/*.png` — 설계서 (모듈 · 위젯 트리 · 데이터 모델 · 신호 흐름)
5. `docs/04_RULES_AND_TESTS.md` — 세대별 규칙과 **반드시 통과해야 할 테스트 값**
6. `design/tokens.json`, `design/Tokens.h`, `design/pokesix.qss` — 바로 가져다 쓸 수 있는 시작 파일
7. `design/source/*.dc.html` — 수치가 궁금할 때 열어 보는 원본 (HTML 인라인 스타일에 px가 그대로 있다)
   - 디자인 도구 형식이라 브라우저로 열면 `{{…}}` · `<sc-for>` 템플릿 때문에 그대로 렌더되지 않는다. **텍스트로 읽어라.** 목록 데이터는 파일 끝 `renderVals()` 안에 있다.

## 4. 작업 순서와 완료 기준

각 단계가 끝나면 짧게 보고하고, 사용자가 확인한 뒤 다음 단계로 간다.

**4-0. 저장소 파악** — 빌드 시스템, Qt 버전, 기존 폴더 구조, 이미 있는 화면을 확인하고 보고. 기존 구조가 있으면 `03_ARCHITECTURE.md`의 구조를 그 위에 맞춰 조정한다(갈아엎지 말 것). 비어 있으면 CMake 프로젝트를 새로 만든다.

**4-1. 토대** — `theme/`(Tokens · TypeColors · Theme::apply · FontLoader), 번들 글꼴(`assets/fonts/README.md` 참고), 아이콘 리소스(`assets/icons/`), 앱 아이콘 설정(macOS icns · Windows ico · Linux hicolor).
완료: 빈 MainWindow가 빨강 앱 막대 + 탭 5개로 뜨고, 세 OS 아이콘이 적용된다.

**4-2. 컴포넌트** — `docs/01_DESIGN_SHEET.md §5`의 위젯 전부. `--gallery` 실행 인자로 컴포넌트 갤러리 창을 띄울 수 있게 한다.
완료: 갤러리 캡처가 `images/screens/02_components.png`와 나란히 봤을 때 같은 규격.

**4-3. 도메인 · 분석** — `TypeChart::forGeneration`, `GenerationRules`, `SquadAnalyzer`. Qt Widgets에 의존하지 않는 순수 코드.
완료: `docs/04_RULES_AND_TESTS.md`의 테스트 전부 QtTest로 통과.

**4-4. 데이터** — SQLite 스키마(`03_ARCHITECTURE.md §5`)와 시드 데이터(목업에 나온 4세대 포켓몬 19종 · 기술 · 진화 아이템). 실제 데이터 가져오기는 원본이 정해진 뒤 별도 작업.
완료: Repository가 시드 DB에서 목록 · 상세 · 기술을 읽는다.

**4-5. 화면** — 홈 → 도감 → 스쿼드 → 아이템 → 설정 순.
완료: 각 화면을 1440×900 창에서 캡처해 `images/screens/1?_*.png`와 비교, 차이 목록을 보고.

**4-6. 반응형** — `ResponsiveController`와 폭 구간별 레이아웃(1360 / 1100 / 1024 / 960).
완료: 1024×768 캡처가 `20_dex_1024_drawer.png`, `21_squad_1024.png`와 일치. 960×640 최소 창에서 잘림 없음.

**4-7. 저장과 설정** — 스쿼드 JSON 저장(디바운스), QSettings, 세대 전환 시 전 화면 재계산.

## 5. 지켜야 할 제약

- Qt Widgets로 구현한다(QML 아님). 복잡한 블러, 연속 애니메이션, 불규칙 곡선 레이아웃 금지. 그림자는 전부 "오프셋 사각형" 한 장.
- 스타일은 가능한 한 QSS + `Theme`로, QSS로 안 되는 것(히트맵, 종족값 바, 창 그림자, 타입 칩)은 `paintEvent`에서 QPainter로.
- 색 · 크기는 하드코딩하지 말고 `Tokens.h` / `TypeColors`에서만 가져온다. 다크 테마는 토큰 교체로 전환되어야 한다.
- 모든 인터랙티브 요소는 키보드로 도달 가능(Tab 순서 = 화면의 읽는 순서), 포커스 링은 파랑 3px. 아이콘만 있는 버튼엔 accessibleName.
- 텍스트 대비 4.5:1 이상. 디자인 시트의 글자색 조합을 바꾸지 말 것.
- 포켓몬 이미지 · 공식 로고 · 포켓볼 도안을 코드나 리소스에 넣지 않는다. 자리표시자 위젯 `SpritePlaceholder`를 쓴다.
- 문구는 캡처와 원본 HTML에 있는 그대로 쓴다(해요체). 새 문구가 필요하면 같은 톤으로 쓰고 보고.

## 6. 검증 방법

- 앱에 `--screenshot <page> <width>x<height> <out.png>` 인자를 만들어 오프스크린으로 화면을 캡처할 수 있게 하라(`QWidget::grab()`).
- 단계마다 캡처를 기준 이미지와 나란히 비교하고, 눈에 띄는 차이(간격 · 색 · 글꼴 · 정렬)를 목록으로 보고한다.
- 분석 로직은 `04_RULES_AND_TESTS.md`의 표를 그대로 테스트 데이터로 쓴다. 숫자 하나라도 다르면 규칙 구현이 틀린 것이다.

## 7. 사용자에게 물어볼 것 (막히면 추측하지 말고 질문)

1. 도감 · 기술 · 아이템 데이터 원본과 라이선스
2. 스프라이트를 끝까지 자리표시자로 둘지
3. 앱 이름 "PokeSix"를 공개 배포에 그대로 쓸지 (상표 검토 필요 여부)
4. 대상 Qt 최소 버전과 각 OS 패키징 방식(dmg · msi/zip · AppImage/flatpak)
