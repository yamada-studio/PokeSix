# 다이아몬드 · 펄 (DP)

공통 구조(슬롯 · footer · 최신 판정 · 게임 판별)는 [README.md](README.md), 포켓몬 한 마리는 [pk4.md](pk4.md).
검증: 실파일 검증 전 — 수치는 PKHeX 기준(◇). 세이브가 생기면 `pokesix-read-sav -v`로 확인한다.

## 1. 요약

| 항목 | 값 | 검증 |
|---|---|---|
| ROM 게임 코드 | `ADA` · `APA` | |
| PK4 출신 게임 값(`0x5F`) | 10 · 11 | ◇ |
| 일반 블록 크기 | `0xC100` (footer `0x14` 포함) | ◇ |
| 보관 블록 | 시작 `0xC100`, 크기 `0x121E0` | ◇ |
| 매직 | `0x20060623` 일본 · 해외판 / `0x20070903` 한국판 | ◇ |

## 2. 일반 블록 지도 (슬롯 시작 기준)

```
0x0000 ┬ 모험 정보 …
0x64 ├ 트레이너 정보 (§3)                                   T
0x94 ├ 파티 수 u8 (1–6)
0x98 ├ 파티 PK4 × 6   (236 B 간격, 빈 자리는 0)
       │  …
0x0624 ├ 가방 (§4)
       │  … 도감 · 진행 플래그 · 포켓치 · 기타 …
0xC100 ┴ (끝 − 0x14부터 footer)
```

파티 n번째(1–6) 포켓몬 = `0x98 + (n − 1) × 0xEC`.

## 3. 트레이너 정보 (T = `0x64` 기준)

```
        +0     +1     +2     +3     +4     +5     +6     +7     
0x00  │                 trainer name (8 × u16)                │
0x08  │                           …                           │
0x10  │     TID     │     SID     │           money           │
0x18  │gender│ lang │badges│avatar│ROMcd │ prog │  —   │  —   │
0x20  │    coins    │    hours    │ min  │ sec  │
```

| 위치 | 이름 | 뜻 | 검증 |
|---|---|---|---|
| `+0x00` | trainer name | 이름, u16 × 8(4세대 글자표), `0xFFFF` 끝 | ◇ |
| `+0x10` | TID | 트레이너 ID(표에 보이는 번호) | ◇ |
| `+0x12` | SID | 비밀 ID — TID와 함께 이로치 판정에 쓰인다 | ◇ |
| `+0x14` | money | 돈 u32(최대 999,999) | ◇ |
| `+0x18` | gender | 0 남 · 1 여 | ◇ |
| `+0x19` | lang | 1 일 · 2 영 · 3 프 · 4 이 · 5 독 · 7 스 · 8 한 | ◇ |
| `+0x1A` | badges | 배지 8개, 비트 하나에 배지 하나 | ◇ |
| `+0x1B` | avatar | 트레이너 카드 · 통신 외형 | ◇ |
| `+0x1C` | ROMcd | DP는 쓰지 않는다 | ◇ |
| `+0x1F` | — | (HGSS의 관동 배지 자리) 쓰지 않는다 | |
| `+0x1D` | prog | 진행 플래그(엔딩 등) | ◇ |
| `+0x20` | coins | 동전 u16 | ◇ |
| `+0x22` · `+0x24` · `+0x25` | hours · min · sec | 플레이 시간(시 u16 · 분 u8 · 초 u8) | ◇ |

## 4. 가방 (기준 `0x0624`)

주머니마다 같은 형식의 칸이 늘어서 있다. **칸 하나 = 4바이트**:

```
  +0      +1      +2      +3
│ 물건 번호 u16  │  개수 u16      │      물건 번호 = 게임 번호(4세대), 0 = 빈 칸
```

| 주머니 | 가방 기준 | 슬롯 기준 | 칸 수(다음 주머니까지 ÷ 4) |
|---|---|---|---|
| 도구 | `+0x000` | `0x0624` | 165 |
| 중요한 물건 | `+0x294` | `0x08B8` | 50 |
| 기술머신 · 비전머신 | `+0x35C` | `0x0980` | 100 |
| 메일 | `+0x4EC` | `0x0B10` | 12 |
| 약 | `+0x51C` | `0x0B40` | 40 |
| 나무열매 | `+0x5BC` | `0x0BE0` | 64 |
| 볼 | `+0x6BC` | `0x0CE0` | 15 |
| 배틀 도구 | `+0x6F8` | `0x0D1C` | — |

- 물건 번호는 **게임 번호**다 — PokéAPI id로 바꾸려면 `item_game_indices`(generation 4). 예) 기술머신01 = 게임 번호 328 
- 마지막 주머니의 칸 수는 다음 영역 경계를 확인하지 않아 비워 둔다
- 전투 분석에서는 **기술머신 주머니**(가르칠 수 있는 기술 후보)와 **배틀 도구 · 약 · 나무열매**(지닐 물건 후보)가 쓰인다

## 5. PC 박스 (보관 블록)

```
보관 블록 기준(슬롯 시작 + 0xC100)
+0x00000  현재 박스 번호 u8 (+ 정렬용 3바이트)
+0x00004  박스 1  [ PK4(136 B) × 30 ]   = 0xFF0 바이트
+0x00FF4  박스 2
   …      박스 n = +0x4 + (n − 1) × 0xFF0        (박스 사이 틈 없음)
+0x11EE4  박스 이름 18개 × 40 B (u16 × 20, 0xFFFF 끝)
+0x121B4  벽지 번호 18개 × u8
+0x121C6  박스 잠금 해제 플래그
```

- 박스 포켓몬은 PK4의 앞 **136바이트**(배틀 스탯 없음) — 같은 방식으로 풀고, 레벨 · 능력치는 계산한다([pk4.md §6](pk4.md#6-박스-포켓몬과의-차이))
- 보관 블록은 일반 블록과 **따로** 최신 슬롯을 판정한다(같은 footer 규칙, 블록 크기만 다르다)
