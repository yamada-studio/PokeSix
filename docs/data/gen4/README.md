# 4세대 세이브 파일 — 큰 구조

다이아몬드 · 펄(DP), 플라티나(Pt), 하트골드 · 소울실버(HGSS) 공통. 시리즈별 상세는 [dp.md](dp.md) · [pt.md](pt.md) · [hgss.md](hgss.md),
포켓몬 한 마리의 구조는 [pk4.md](pk4.md).

## 1. 파일 전체

```
.sav  512 KiB (0x80000)            ※ DeSmuME .dsv는 끝에 122바이트가 더 붙는다 — 앞 512 KiB만 본다
┌────────────────────────────────────── 0x00000  슬롯 0 ─────────────────────────────────────┐
│ 일반(general) 블록  [ 트레이너 · 파티 · 가방 · 도감 · 진행 … │ footer ]                     │
│ (HGSS만: 0xD8바이트 틈)                                                                     │
│ 보관(storage) 블록  [ PC 박스 18개 · 박스 이름 · 벽지 … │ footer ]                          │
│ (그 뒤: 명예의 전당 · 배틀 비디오 등 부가 블록 — 이 문서 범위 밖)                            │
├────────────────────────────────────── 0x40000  슬롯 1 ─────────────────────────────────────┤
│ 슬롯 0과 같은 모양의 사본                                                                   │
└─────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 게임은 저장할 때마다 **두 슬롯에 번갈아** 쓴다. 쓰다가 전원이 꺼져도 다른 슬롯에 직전 저장이 남는다(A/B 이중 버퍼)
- 일반 블록과 보관 블록은 **따로** 최신 판정을 한다(박스를 안 건드린 저장은 보관 블록을 다시 쓰지 않을 수 있다). 파티만 읽을 때는 일반 블록만 보면 된다

## 2. 세 시리즈 비교 — 코드의 `kNdsSeries` 표(4세대 행)와 같은 값

모든 오프셋은 **슬롯 시작 기준**(슬롯 1이면 0x40000을 더한다).

| | DP | Pt | HGSS | 검증 |
|---|---|---|---|---|
| 일반 블록 크기(footer 포함) | `0xC100` | `0xCF2C` | `0xF628` | HGSS ✓ |
| footer 길이(CRC 범위에서 뺌) | `0x14` | `0x14` | `0x10` | HGSS ✓ |
| 보관 블록 시작 | `0xC100` | `0xCF2C` | `0xF700` | ◇ |
| 보관 블록 크기 | `0x121E0` | `0x121E4` | `0x12310` | ◇ |
| 트레이너 정보 | `0x64` | `0x68` | `0x64` | HGSS ✓ |
| 파티 수(u8) | `0x94` | `0x9C` | `0x94` | HGSS ✓ |
| 파티(236 × 6) | `0x98` | `0xA0` | `0x98` | HGSS ✓ |
| 가방 시작 | `0x624` | `0x630` | `0x644` | HGSS ✓ |
| 박스 1번 | 보관 + `0x4`, 간격 `0xFF0` | 보관 + `0x4`, 간격 `0xFF0` | 보관 + `0x0`, 간격 `0x1000` | ◇ |

규칙: 파티 수는 항상 **파티 시작 − 4**에 있다.

## 3. footer — 블록의 끝 (일반 · 보관 블록 공통 규칙)

위치는 모두 **블록 끝**(블록 시작 + 블록 크기) 기준이다.

```
         끝−0x14   끝−0x10   끝−0x0C   끝−0x08   끝−0x04   끝−0x02
       │ major u32│ minor u32│ 크기 u32 │ 매직 u32 │ ? u16 │ CRC u16 │
```

| 칸 | 위치 | 뜻 | 검증 |
|---|---|---|---|
| major | 끝 − 0x14 | 저장 카운터(상위). **HGSS에서는 두 슬롯 모두 0** | HGSS ✓ |
| minor | 끝 − 0x10 | 저장 카운터(하위). HGSS의 실제 저장 횟수(예: 100 · 99) | HGSS ✓ |
| 크기 | 끝 − 0x0C | 블록 크기 = 위 표의 일반 블록 크기 | HGSS ✓ (`28 f6 00 00`) |
| 매직 | 끝 − 0x08 | `0x20060623` 일본 · 해외판 / `0x20070903` 한국판 | 한국판 ✓ |
| CRC | 끝 − 0x02 | 블록 데이터 `[시작, 끝 − footer 길이)`의 CRC-16/CCITT-FALSE | HGSS ✓ |

- HGSS는 footer가 0x10이라 끝 − 0x14(major)가 **CRC 범위 안**의 블록 데이터 끝에 놓인다. 판정 규칙(끝 − 0x14 · − 0x10 비교)은 세 시리즈가 같다
- CRC-16/CCITT-FALSE: 다항식 `0x1021`, 초깃값 `0xFFFF`, 비트 반사 없음, 마지막 XOR 없음. 검증 값 "123456789" → `0x29B1`

### 최신 슬롯 판정

```
1. 두 슬롯의 footer를 읽는다
2. CRC가 맞지 않는 슬롯은 버린다     (쓰다 끊긴 슬롯 · 한 번도 안 쓴 슬롯 = 0xFF로 채워져 CRC 불일치)
3. 둘 다 남으면 (major, minor)를 사전식으로 비교해 큰 쪽 — 같으면 슬롯 0
4. 둘 다 버려지면 이 시리즈의 세이브가 아니거나 깨진 세이브
```

## 4. 세이브만으로 게임 판별

블록 크기가 시리즈마다 달라서, **다른 시리즈의 크기로 읽으면 엉뚱한 곳을 footer로 읽어 CRC가 맞을 수 없다.**
그래서 세 표(DP · Pt · HGSS)를 차례로 시도해 CRC가 맞는 표가 그 시리즈다. ROM 없이 판별된다.

같은 시리즈 안의 버전(다이아 ↔ 펄, 하트골드 ↔ 소울실버)은 세이브 구조로는 구별되지 않는다.
구별하려면 파티 포켓몬의 **출신 게임 바이트**(PK4 `0x5F`, 그 게임에서 잡은 포켓몬이면 그 버전) 또는 ROM 헤더를 본다.

| ROM 게임 코드(헤더 0x0C, 앞 3글자) | 게임 | PK4 출신 게임 값(`0x5F`) |
|---|---|---|
| `ADA` · `APA` | 다이아몬드 · 펄 | 10 · 11 |
| `CPU` | 플라티나 | 12 |
| `IPK` · `IPG` | 하트골드 · 소울실버 | 7 · 8 |

(ROM 코드 4번째 글자는 지역: J 일본 · E 미국 · K 한국 · O 유럽 등. ROM은 헤더 외에 읽지 않는다.)

## 5. 글자 인코딩

트레이너 이름 · 별명은 **4세대 전용 16비트 글자표**다(UTF-16 아님). 한 글자 = u16, 끝은 `0xFFFF`.
한국판은 한글 글자 코드가 따로 있다. 이름을 화면에 쓰려면 글자표가 필요하다 — 아직 정리하지 않았다(전투 분석에는 필요 없다).
