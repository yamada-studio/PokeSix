# 게임 데이터 구조 지도 — 세이브 · 포켓몬 데이터의 바이트 배치

게임 세이브(`.sav`)와 그 안의 포켓몬 데이터가 **몇 번째 바이트에 무엇이 있는지**를 세대 · 시리즈별로 정리한 참고서다.
H1(세이브 읽기)의 정답지이고, 나중에 **전투 분석 · 시뮬레이션**을 만들 때 "어떤 값을 어디서 가져오나"의 기준이 된다.

> 코드가 아니라 **사실(오프셋 · 크기 · 비트 의미)**만 적는다. 출처는 PKHeX(GPL-3.0 — 수치만 참고, 코드는 옮기지 않는다) ·
> Bulbapedia · Project Pokémon 문서이고, 문장은 이 리포의 말로 다시 썼다([docs/i18n/README.md](../i18n/README.md#저작권-원칙)).

## 디렉토리

```
docs/data/
├ README.md            이 문서 — 표기법 · 진행 현황
├ battle-inputs.md     전투 시뮬에 필요한 값: 세이브에서 · DB에서 · 계산해서
├ gen4/                4세대 (NDS)
│  ├ README.md         세이브 파일의 큰 구조(슬롯 · 블록 · footer), 세 시리즈 비교표, 게임 판별
│  ├ pk4.md            포켓몬 한 마리(PK4, 236바이트)의 전체 지도 · 암호화 · 비트 필드 · 파생 값 · 능력치 공식
│  ├ dp.md             다이아몬드 · 펄
│  ├ pt.md             플라티나
│  └ hgss.md           하트골드 · 소울실버
└ gen5/                5세대 (NDS)
   └ README.md         BW · B2W2 세이브 구조(체크섬 모음 블록 · 파티 블록), 게임 판별, PK5가 PK4와 다른 칸
```

다른 세대는 그 세대를 다룰 때 같은 모양으로 더한다. 세대를 세이브만으로 판별하는 형식 표(`src/core/save/saveformat.h`)는 로드맵 H6 —
설계는 [overlay-design.md §5](../overlay-design.md#5-세이브-파싱--core에-둔다-qt-없음)의 "여러 세대를 자동 판별하는 구조".

| 세대 | 시리즈 | 세이브 구조 | 포켓몬 구조 | 실파일 검증 |
|---|---|---|---|---|
| 4 | DP | ✅ | ✅ PK4 | ◇ (세이브 없음) |
| 4 | Pt | ✅ | ✅ PK4 | ◇ (세이브 없음 — 사용자 Pt 세이브 생기면 확인) |
| 4 | HGSS | ✅ | ✅ PK4 | ✓ 소울실버 한국판 (2026-10-08) |
| 5 | BW · B2W2 | ◇ | ◇ PK5(PK4와 다른 칸만) | ◇ (세이브 없음 — 합성 세이브로만 확인) |
| 1–3, 6– | — | — | — | 계획 없음 |

## 표기법

### 검증 표시

| 표시 | 뜻 |
|---|---|
| ✓ | 실제 세이브 파일에서 값을 읽어 확인했다 |
| ◇ | 출처(PKHeX 등)의 수치만 있고 실파일로는 아직 확인하지 않았다 |
| ★ | 전투 분석 · 시뮬에 쓰이는 칸([battle-inputs.md](battle-inputs.md)) |

### 바이트 지도 (byte map)

한 줄에 8바이트. 칸 이름 아래 `u8` · `u16` · `u32`는 크기(리틀 엔디언 부호 없는 정수)다.

```
         +0     +1     +2     +3     +4     +5     +6     +7
0x00  │ PID u32 ─────────────────────│ 플래그 u16  │ 체크섬 u16  │
0x08  │ 종 u16      │ 물건 u16     │ 트레이너 ID u32 ────────────│
```

### 비트 지도 (bit map)

한 칸 안에 여러 값이 비트로 들어 있을 때. 왼쪽이 높은 비트(31), 오른쪽이 낮은 비트(0).

```
비트  31  30  29───25  24───20  19───15  14───10  9────5  4────0
     별명 알    특방     특공     스피드    방어     공격    HP
```

### 수치 규칙

- 오프셋은 16진수(`0x98`). "블록 기준" · "PKM 기준"처럼 무엇에서부터 센 위치인지 표 머리에 적는다
- 모든 다바이트 정수는 **리틀 엔디언**(낮은 바이트가 앞) — DS는 리틀 엔디언이다
- "게임 번호"는 게임 내부의 번호, "PokéAPI id"는 DB의 id. 같은 것(종 · 기술 · 특성)과 다른 것(물건 · 성격)이 있다 — 각 표에 적는다
