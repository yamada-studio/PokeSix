# 5세대 세이브 파일 — 큰 구조 (BW · B2W2)

블랙 · 화이트(BW), 블랙2 · 화이트2(B2W2) 공통. 4세대와 비교하며 읽도록 썼다 — 4세대는 [gen4/README.md](../gen4/README.md),
PK4는 [gen4/pk4.md](../gen4/pk4.md). 구현 가이드: [guides/h6-multigen-save.md](../../guides/h6-multigen-save.md).

> **이 문서의 수치는 모두 ◇**(PKHeX `SaveUtil` · `SAV5` · `SaveBlockAccessor5BW/B2W2` · `PK5`의 값, 실파일 미검증).
> 코드는 이 값으로 만든 합성 세이브(`tests/core/syntheticsave.h`의 `buildGen5Save`)로만 확인했다.
> BW · B2W2 세이브가 생기면 `POKESIX_SAVE_BW` · `POKESIX_SAVE_B2W2`로 `RealSave` 테스트를 돌려 ✓로 바꾼다.

## 1. 파일 전체

```
.sav  512 KiB (0x80000)        ← 4세대와 같은 크기 — 크기로는 세대를 못 가린다
┌──────────────────────────────── 0x00000  본 세이브(main) ────────────────────────────────┐
│ …                                                                                         │
│ 0x18E00  파티 블록 (0x534 B)                                                              │
│ 0x19336  파티 블록의 CRC (u16)                                                            │
│ …                                                                                         │
│ 끝 − 0x100  체크섬 모음 블록 — 본 세이브의 블록 CRC들을 한 곳에 다시 모은 표              │
├──────────────── 끝 = 0x24000 (BW) · 0x26000 (B2W2) ───────────────────────────────────────┤
│ 이 뒤 — 이 문서 범위 밖(PokeSix는 본 세이브만 읽는다)                                     │
└───────────────────────────────────────────────────────────────────────────────────────────┘
```

- 4세대처럼 두 슬롯을 **번갈아 쓰지 않는다** → "최신 슬롯 판정"이 없다
- 블록의 CRC는 블록 바로 뒤에 한 번, 체크섬 모음 블록 안에 **사본으로 한 번 더** 있다

## 2. 두 시리즈 비교 — 코드의 `kNdsSeries` 표(5세대 행 · `ChecksumTable`)와 같은 값

| | BW | B2W2 | 검증 |
|---|---|---|---|
| 본 세이브 크기 | `0x24000` | `0x26000` | ◇ |
| 체크섬 모음 블록 시작(끝 − `0x100`) | `0x23F00` | `0x25F00` | ◇ |
| 체크섬 모음 블록 길이 | `0x8C` | `0x94` | ◇ |
| 모음 블록 자신의 CRC 위치(시작 + 길이 + `0x0E`) | `0x23F9A` | `0x25FA2` | ◇ |
| 파티 블록 | `0x18E00`, 길이 `0x534` | 같다 | ◇ |
| 파티 블록 CRC | `0x19336` | 같다 | ◇ |
| 파티 블록 CRC 사본 | 모음 블록 + `0x34` | 같다 | ◇ |

### 파티 블록 — 블록 기준

| 위치 | 크기 | 칸 | 검증 |
|---|---|---|---|
| `+0x00` | u32 | (파티 앞 머리 — 읽지 않는다) | |
| `+0x04` | u8 | 파티 수 1–6 ★ | ◇ |
| `+0x08` | 220 B × 6 | PK5 파티 레코드 ★ | ◇ |

4세대의 "파티 수 = 파티 시작 − 4" 규칙이 5세대에서도 성립한다(`+0x04` · `+0x08`).

## 3. CRC

- 함수는 4세대와 **같은** CRC-16/CCITT-FALSE(다항식 `0x1021`, 초깃값 `0xFFFF`) — `crc16Ccitt`
- 체크섬 모음 블록 CRC = `crc16Ccitt([모음 블록 시작, + 길이))`, 저장 위치는 모음 블록 + 길이 + `0x0E`
- 파티 블록 CRC = `crc16Ccitt([0x18E00, + 0x534))`, 저장 위치 두 곳(`0x19336`, 모음 블록 + `0x34`)
- 사본이 모음 블록 **안**에 있으므로, 게임이 저장할 때(그리고 합성 세이브를 만들 때)는 **파티 CRC → 사본 → 모음 블록 CRC** 순서로 써야 맞는다

## 4. 세이브만으로 게임 판별

4세대와 같은 원리를 한 단계 위에서 쓴다.

```
세대:   4세대 형식(DP · Pt · HGSS의 footer CRC) → 5세대 형식(BW · B2W2의 모음 블록 CRC) 차례로 — 맞는 형식이 그 세대
시리즈: 5세대 안에서는 BW · B2W2 행마다 "본 세이브 크기 − 0x100에 모음 블록이 있다"고 가정해 CRC를 맞춰 본다
```

본 세이브 크기가 다르면 모음 블록 자리가 달라서, 다른 시리즈의 가정으로는 CRC가 맞을 수 없다.
같은 시리즈 안의 버전(블랙 ↔ 화이트, 블랙2 ↔ 화이트2)은 4세대처럼 파티 포켓몬의 **출신 게임 바이트**로 가린다.

| ROM 게임 코드(헤더 0x0C, 앞 3글자) | 게임 | PK5 출신 게임 값(`0x5F`) |
|---|---|---|
| `IRB` · `IRA` | 블랙 · 화이트 | **21 · 20** (블랙이 큰 수) |
| `IRE` · `IRD` | 블랙2 · 화이트2 | **23 · 22** |

## 5. PK5 — PK4와 다른 칸만

전체 지도는 [gen4/pk4.md](../gen4/pk4.md)를 그대로 쓰고, 아래 차이만 덮어 읽는다.

| | PK4 | PK5 | 검증 |
|---|---|---|---|
| 파티 레코드 | 236 B (`0xEC`) = 136 + 배틀 스탯 100 | **220 B (`0xDC`)** = 136 + 배틀 스탯 **84** | ◇ |
| 암호화 · 블록 섞기 · 체크섬 | LCRNG XOR · `((pid >> 13) & 0x1F) % 24` · u16 합 | 같다 | ◇ |
| 배틀 스탯 앞부분(`0x88–0x9B`) 상태 · 레벨 · HP · 능력치 | §배틀 스탯 표 | 같은 위치 | ◇ |
| `0x41` u8 | HGSS 빛나는 잎 | **성격 ★** — 게임 순서 0–24(4세대 `pid % 25`와 같은 순서) | ◇ |
| `0x42` u8 비트 0 | 안 씀 | **숨겨진 특성 ★** (1이면 `0x15`의 특성이 숨겨진 특성) | ◇ |
| `0x5F` u8 출신 게임 | 7 · 8 · 10 · 11 · 12 | 20 W · 21 B · 22 W2 · 23 B2 (그 이하 = 4세대에서 옮겨 온 것) | ◇ |
| 종 · 기술 · 특성 번호 | PokéAPI id와 같다 | 같다(종 ≤ 649) | ◇ |
| 물건 번호 | 4세대 게임 번호 | **5세대 게임 번호** — DB `item_generations`(generation 5)의 `game_index` | ◇ |

**성격을 따로 저장하는 이유**: 5세대부터 싱크로 · 변하지않는돌처럼 PID와 상관없이 성격을 정하는 방법이 생겨서,
PID에서 계산하지 않고 값을 따로 둔다. 그래서 5세대에서 `pid % 25`로 읽으면 틀린 성격이 나온다.

**220 B를 PK4 디코더로 풀 수 있는 이유**: 배틀 스탯은 PID로 시작한 난수열을 앞에서부터 XOR하는 스트림이라,
84 B를 푸는 난수는 100 B를 풀 때의 앞부분과 같다. 길이만 다르게 주면 된다.

## 6. 글자 인코딩

5세대 이름 · 별명은 UTF-16에 가까운 16비트 글자(일부 특수 글자만 게임 전용 코드)다 — 4세대의 전용 글자표보다 다루기 쉽다. ◇, 아직 읽지 않는다.
