# 번역 · 공략 데이터 보충 요청

PokéAPI에 없는 정보를 앱의 로컬 사전으로 모은다. 웹 검색 AI에게 맡길 일감은 두 가지다.

1. **이름 · 설명 번역**: 한국어 이름과 설명문이 비어 있는 항목. 세대와 상관없는 값이다.
2. **게임별 입수 사전**: 게임(버전 그룹)마다 아이템·기술머신을 어디서 어떻게 얻는지와 NPC 가르침 비용. 같은 세대라도 게임마다 다르다.

PokéAPI가 이미 게임 단위로 주는 정보는 요청하지 않는다. 기술머신에 담긴 기술(`machines` 표)과 NPC 가르침으로 배울 수 있는 기술 목록이 여기에 해당한다. 요청서에 이미 채워져 있다.

## 1. 이름 · 설명 번역

| 요청서 | 항목 수 | 옮겨 갈 사전 |
|---|---|---|
| [places-request.json](places-request.json) | 장소 680 (지방별로 묶음) | `resources/data/place-names.json` |
| [names-request.json](names-request.json) | 아이템 34 · 기술 18 · 특성 3 · 버전 5 | `resources/data/names.json` |
| [effects-request.json](effects-request.json) | 설명문: 아이템 51 · 기술 88 · 특성 47 | `resources/data/names.json` |

도로·수로 번호("201번 도로", "220번 수로")는 앱이 규칙으로 만든다. 그래서 요청서에서 뺐다.

```text
첨부한 JSON은 포켓몬 게임 데이터 중 한국어 표기가 비어 있는 항목 목록입니다.
각 항목의 빈 "ko" 칸(있으면 "ja" 칸도)을 채워서, 같은 구조의 JSON으로 돌려주세요.

규칙
1. 공식 한국어 표기를 쓰세요. 우선순위: 한국 정발 게임 화면 표기 > 포켓몬코리아 공식 사이트 > 포켓몬 위키(pokemonwiki) 표기.
2. 같은 장소가 리메이크에서 이름이 바뀌었다면 가장 최근 정발판 표기를 쓰세요.
   (예: 관동·성도 → 하트골드·소울실버 / 레츠고, 호연 → 오메가루비·알파사파이어, 신오 → 플라티나 / 브릴리언트다이아몬드·샤이닝펄)
3. 한국에 정발되지 않은 게임의 항목(오레 지방, 콜로세움·XD의 다크 기술 등)은 포켓몬 위키의 관용 표기를 쓰고,
   그 항목에 "note": "비공식" 을 붙이세요.
4. 설명문(effects)은 그 기술·아이템·특성의 한국어판 게임 설명문을 그대로 옮기세요. 9세대(스칼렛·바이올렛) 설명이 있으면 그것을 우선합니다.
   설명문을 직접 번역하지 마세요. 공식 문구를 못 찾으면 "ko"를 빈 칸으로 두고 "note": "못 찾음" 을 붙이세요.
5. 확신이 없는 값은 지어내지 말고 "note": "불확실 — <이유>" 를 붙이세요.
6. "en", "seen_in", "name_en" 같은 기존 칸은 그대로 두세요(대조용입니다).
7. 키(PokéAPI identifier, 예: "oreburgh-mine")는 절대 바꾸지 마세요.
8. 출처 URL을 파일 맨 위 "_sources" 배열에 모아 주세요.
```

## 2. 게임별 입수 사전

[acquisition/](acquisition/)에 게임(버전 그룹)마다 파일이 하나씩 있다. 1세대 레드·그린부터 9세대 DLC까지 30개다.
각 파일에는 다음이 미리 들어 있다.

- `_tms`: 그 게임의 기술머신 표(PokéAPI). 아이템 identifier → 담긴 기술.
- `_tutors`: 그 게임에서 NPC 가르침으로 배울 수 있는 기술(PokéAPI).
- `items`: 기술머신 키가 빈 배열로 들어 있다. 플라티나는 사용자가 블로그에서 옮긴 기술머신 획득처가 이미 들어 있다.
- `tutors`: 가르침 기술 키가 빈 배열로 들어 있다. 에메랄드는 펀치 3종이 이미 들어 있다.

참조용 목록도 있다.

- [item-ids.json](item-ids.json): 아이템 identifier → 영어·한국어 이름 (2,174개)
- [location-ids.json](location-ids.json): 장소 identifier → 영어 이름·지방 (1,104개)

PokéAPI 쪽 기술머신 표가 덜 채워진 게임이 있다. BDSP는 17개뿐이다(실제는 100개). 이런 게임은 빠진 기술머신도 `items`에 더해 달라고 한다.
DLC(갑옷의 외딴섬, 왕관의 설원)와 Champions는 기술머신 표가 없다.

### 입수 방법 한 칸의 형식

```json
"tm13": [
  { "how": "shop", "where": "veilstone-city", "place": "장막시티 백화점 4층", "cost": [{ "amount": 10000, "unit": "money" }] },
  { "how": "prize", "where": "veilstone-city", "content": "게임코너", "cost": [{ "amount": 4000, "unit": "coins" }] }
]
```

| 칸 | 뜻 | 값 |
|---|---|---|
| `how` | 방법 | `field` 필드에서 줍기 · `hidden` 숨겨진 아이템 · `gift` NPC가 줌 · `shop` 상점 · `exchange` 포인트 교환(BP·조각 등) · `prize` 게임코너 경품 · `reward` 배틀·이벤트 보상 · `held` 야생 포켓몬 소지(드롭) · `trade` 교환 · `tutor` NPC 가르침 · `other` |
| `where` | 장소 | PokéAPI 장소 identifier ([location-ids.json](loc<!--  -->ation-ids.json)에서 고른다). 없으면 생략 |
| `place` | 장소 글자 | `where`로 부족할 때 쓴다. 층·건물처럼 세부 위치를 적는다(한국어) |
| `content` | 컨텐츠 | 배틀프런티어, 배틀서브웨이, 포케슬론, 게임코너 등. 한국어 글자 또는 `{ko, en, ja}` |
| `cost` | 비용 | `[{amount, unit}]`. 여러 개면 합쳐서 낸다. unit: `money`(원) · `bp` · `coins` · `red-shard`·`blue-shard`·`yellow-shard`·`green-shard` · `heart-scale` · `athlete-points`(포케슬론) · `watts` · `league-points`. 목록에 없는 단위는 영어 소문자-하이픈으로 |
| `detail` | 조건·메모 | "파도타기 필요", "엔딩 후", "관장 승리 보상", "목요일만" 등(한국어) |

```text
첨부한 JSON은 포켓몬 게임 하나(versionGroup)의 아이템 입수 사전 양식입니다.
"_games"에 적힌 게임 기준으로, 아래를 채워 같은 구조의 JSON으로 돌려주세요.

1. items: 미리 들어 있는 기술머신(tm·hm·tr) 키마다 입수 방법 배열을 채우세요("_tms"에 담긴 기술이 적혀 있습니다).
   이미 값이 있으면 확인만 하고, 틀린 것만 고치세요.
2. items: 그 게임에서 얻을 수 있는 나머지 아이템도 전부 더하세요. 우선순위: 진화 도구 → 지닌 물건 → 배틀 도구 →
   나무열매 → 몬스터볼 → 회복약 → 중요한 물건. 메일과 미사용 데이터는 빼세요.
   키는 item-ids.json의 identifier를 쓰세요(영어 이름을 소문자-하이픈으로 바꾼 꼴입니다. 예: "fire-stone").
3. tutors: 미리 들어 있는 기술 키마다 NPC 가르침의 장소·비용을 채우세요. 공짜면 cost를 생략하고, 1회 한정이면 detail에 적으세요.
4. 각 입수 방법은 형식표(how · where · place · content · cost · detail)를 따르세요. where는 location-ids.json의 identifier만 쓰세요.
5. 같은 아이템을 여러 곳에서 얻으면 전부 적으세요(필드 · 상점 · 경품을 모두).
6. 그 게임에서 얻을 수 없는 아이템은 넣지 마세요(넣지 않음 = 이 게임에 없음으로 처리됩니다).
7. 장소 · 조건 글자는 한국어 정발판 표기로 쓰세요. 확신 없는 항목에는 "note": "불확실 — <이유>"를 붙이세요.
8. "_" 로 시작하는 칸(_games, _tms, _tutors)은 그대로 두고, 출처 URL은 "_sources"에 더하세요.
9. 키(versionGroup, 아이템·기술 identifier)는 바꾸지 마세요.
```

한 번에 한 게임씩 맡긴다. 큰 게임(SV 등)은 기술머신 → 나머지 아이템 → 가르침 순서로 나눠서 받아도 된다.

## 돌아온 뒤

채워진 JSON을 받으면 Claude가 다음 순서로 옮긴다.

1. 이름 · 설명은 `place-names.json`과 `names.json`에, 입수 사전은 `resources/data/acquisition/<게임>.json`에 넣는다.
2. 넣으면서 검증한다. 모르는 identifier와 `"note": "불확실"` 항목은 따로 목록으로 남긴다.
3. 빌드하고 화면에서 확인한다.

사전은 실행 중에 읽는다(`data/text/namebook.h`, `ui/dex/guidebook.h`). 그래서 데이터를 다시 받지 않아도 된다.
입수 사전에 기술머신 말고 다른 아이템이 하나라도 있는 게임은, 아이템 백과가 그 목록으로 "이 게임에서 얻을 수 있는 아이템"만 보여 준다.
