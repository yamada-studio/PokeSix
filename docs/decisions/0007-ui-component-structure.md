# 0007. UI 컴포넌트는 "그리기 · 동작 · 겉모양"을 나눠 모듈화한다

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락

홈 화면을 그리기 시작하기 전에(A2), 화면마다 반복될 컴포넌트를 어떤 단위로 나눌지 정해야 했다.
디자인 시트([01 §4–§5](../design-handoff/docs/01_DESIGN_SHEET.md))와 홈 캡처를 보면 다음이 보인다.

- 같은 "창" 그림(먹색 2px 테두리, 반경 8, 블러 없는 오프셋 그림자, 컬러 머리)이 세 가지 변형으로 반복된다
  - 머리 38 + 본문: 최근 스쿼드 → 모든 화면의 패널
  - 큰 머리 78 + 선택 테: 세대 카드 → 스쿼드 슬롯 카드, 테마 미리보기 카드
  - 머리 없음 · 채움 변형: 바로 가기 카드
- 이 가운데 일부는 **클릭할 수 있는 카드**(포커스, 키보드, `clicked`)이고, 일부는 **컨테이너**다
- 선택 테(바깥 4px, 간격 3px)와 포커스 링(바깥 3px, 간격 2px)은 **상자 바깥**에 그려진다.
  Qt 위젯은 자기 rect 밖에 그릴 수 없다(자식은 부모 안에서 잘린다)
- 모달은 디자인에 없다. 설계서에 "다이얼로그 3종(포켓몬 선택 = 도감 목록 재사용, 기술 선택, 세대 메뉴)"이라는 언급만 있고,
  셋 다 스쿼드 화면(Phase E)에서 처음 필요하다. 세대 메뉴는 `QMenu`다. 드로어(좁은 창의 상세)도 Phase F다

## 선택지

1. **창 하나를 베이스 클래스로 두고 모든 카드가 상속한다** — 단순하다 / 클릭 카드는 `QAbstractButton`의
   포커스 · 키보드 · 접근성이 필요한데, 다중 상속이나 기능 재구현이 필요하다
2. **그리기를 상태 없는 함수로 분리하고, 베이스 클래스는 동작으로 고른다** — 그리는 코드는 한 곳, 위젯은
   역할에 맞는 Qt 클래스를 쓴다 / 함수와 스타일 구조체 하나가 더 생긴다
3. **모달 · 드로어 프레임워크를 지금 만든다** — 나중에 편하다 / 시각 설계가 없고, 홈에는 쓸 곳이 없다

## 결정

선택지 2를 채택하고, 모달 · 드로어는 만들지 않되 경계만 정한다.

1. **그리기 레시피는 함수 하나.** `paintPanel(QPainter&, const QRect&, const PanelStyle&)`이 테두리 · 그림자 · 머리를 그린다.
   컨테이너 `PanelFrame`(`QWidget`), 클릭 카드(`QAbstractButton`), 나중의 모달 겉모양이 모두 이 함수를 부른다 (A5)
2. **베이스 클래스는 동작으로 고른다.** 클릭 · 선택이 있으면 `QAbstractButton`(checkable이면 `QButtonGroup`으로 단일 선택),
   아니면 `QWidget`
3. **내용 위젯은 자기를 감싼 겉모양(chrome)을 모른다.** 겉모양은 `PanelFrame`(화면 안) · 드로어 · 모달 중 하나이고,
   내용은 그 안에 끼워질 뿐이다. 겉모양의 두께(테두리 + 머리 + 그림자)는 겉모양 위젯의 `contentsMargins`로 확보한다
4. **위젯 rect = 상자 + 아래 그림자.** 그림자(아래 3–4px)는 위젯 rect 안에 그린다. 그래서 세로 간격은
   `디자인 gap − 그림자`로 환산한다(예: gap 12, 그림자 4 → spacing 8)
5. **상자 바깥 장식(선택 테 · 포커스 링)은 위젯 스스로 그리지 않는다.** 방식(부모가 그리기 vs `QFocusFrame`처럼
   대상 위를 덮는 형제 위젯)은 선택이 처음 등장하는 A6에서 정한다. 그래서 그리드 컨테이너는 가장자리 여백을 남긴다
   (디자인의 `padding: 6px 4px 0`)
6. **`ui/widgets/`로 올리는 기준:** 디자인 시트 §5에 컴포넌트로 올라 있거나 두 화면 이상에서 쓰는 것.
   그 밖은 화면 폴더(`ui/home/` …)에 둔다. widgets는 화면 폴더를 include하지 않는다
7. **디자인 시트 → 코드는 `ui/theme` 한 곳.** 원색 토큰(`red`, `blue` …) 위에 **의미 역할**
   (01 §5-2: 빨강 = 주 콘텐츠, 파랑 = 필터 · 분석 · 정보, 초록 = 분류, 노랑 = 보조, 먹색 = 설정 목록)을 두고,
   위젯은 역할을 쓴다 (A4)
8. **CMake 타깃은 `pokesix_ui` 하나로 유지한다.** 6의 include 방향은 컨벤션으로 지키고, Phase B 갤러리가
   widgets만 링크해야 할 때 분리를 다시 검토한다
9. **모달 · 드로어는 Phase E 전에 정한다**([roadmap 열린 질문](../roadmap.md#열린-질문-해당-단계-전에-결정)).
   현재 기울기는 **창 안 오버레이**(dim + `PanelFrame`)다. 드로어도 겹쳐 그려야 하므로 한 방식으로 둘을 처리할 수 있고,
   frameless · 반투명 `QDialog`가 Linux 합성기 유무에 따라 다르게 보이는 문제를 피한다.
   대가는 Esc · 포커스 가두기 · 입력 차단을 직접 구현하는 것이다

## 결과

- 그림자 수치 · 다크 테마 · 반경을 바꿀 때 고칠 곳이 `paintPanel`과 토큰뿐이다
- "포켓몬 선택 = 도감 목록 재사용"이 내용 위젯을 모달에 끼우는 것만으로 된다
- 디자인의 CSS 수치(`gap`, `box-shadow`)를 Qt 간격으로 옮길 때 그림자만큼 환산해야 한다(A2 가이드 표)
- 다시 볼 조건: 컴포넌트 갤러리(Phase B)에서 widgets만 따로 링크해야 할 때, 모달 시각 설계가 들어올 때
