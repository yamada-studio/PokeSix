# 0018 — 세이브(.sav)는 읽기 전용으로, 스쿼드 "불러오기"에서 받는다

- 상태: 채택 (2026-10-08)
- 관련: [overlay-design.md](../overlay-design.md)(검토 문서 — 이 ADR이 1단계를 확정한다) · [ADR 0006](0006-semver-and-trunk-based-branches.md) · 로드맵 Phase H

## 배경

[overlay-design.md](../overlay-design.md)는 에뮬레이터 세이브에서 파티를 읽는 방법을 검토했지만, 두 가지가
열려 있어 시작하지 못했다(사용자, 2026-10-08):

1. **화면을 어디에 둘까** — 인트로 메뉴 · 앱 막대 탭은 이미 꽉 찼다(도감 · 스쿼드 · 아이템 · 타운맵 · 설정)
2. **읽기만 할까, PKHeX처럼 고쳐서 내보내기까지 할까**

## 결정

1. **새 화면을 만들지 않는다.** `.sav`는 "파티 6마리가 든 또 하나의 스쿼드 파일"로 보고, 스쿼드 페이지의
   **불러오기**가 받는 형식에 더한다(`*.pks *.json` → `*.pks *.json *.sav`). 게임은 세이브 구조로 판별하고,
   `.pks` 불러오기처럼 "소울실버 스쿼드로 바꿀까요?" 확인 뒤 세대 · 게임을 전환한다
2. **읽기 전용.** 세이브에 쓰지 않는다 — 편집 · 내보내기(세이브로 되쓰기)는 하지 않는다
   - 쓰기는 블록 CRC · PKM 체크섬 · 암호화 · 섞기를 전부 정확히 되돌려야 하고, 한 바이트만 틀려도
     **진행 중인 실제 세이브를 망가뜨린다.** 되돌릴 수 없는 손해다
   - 세이브 편집은 PKHeX가 이미 잘 한다. PokeSix의 가치는 "읽어서 분석"이다
   - 수요가 생기면 새 ADR로 다시 연다
3. **1차는 4세대(DP · Pt · HGSS).** 사용자가 지금 플레이하는 Pt · SS 세이브로 검증할 수 있다. 5세대는
   같은 구조에 표의 행만 더한다(overlay-design.md H6)
4. **파서는 core(`core/save/`), 사용자가 직접 구현한다(학습 루프).** 가이드:
   [h1-save-reader.md](../guides/h1-save-reader.md). 디버깅용 CLI `pokesix-read-sav`(tools/)로 단계별
   로그를 본다. 게임 내부 번호 → PokéAPI id 변환과 불러오기 UI는 data · ui 레이어의 다음 단계(H2)
5. **세이브 파일은 리포 밖에 둔다.** `.gitignore`에 `*.sav *.dsv *.nds`. 테스트는 합성 세이브를 만들고,
   본인 세이브 테스트는 환경 변수(`POKESIX_SAVE_PT` · `POKESIX_SAVE_HGSS`)가 있을 때만 돈다

## 결과

- overlay-design.md의 "1차 범위 · 읽기 전용"과 같은 방향이다. 오버레이 창(H3 이후)은 그대로 후보로 남고,
  만들게 되면 이 파서를 그대로 쓴다
- PKHeX(GPL-3.0)는 수치만 참고한다 — 코드는 직접 쓴다(MIT 리포)
