# 0008. 홈 화면을 전체 화면 인트로(타이틀)로 바꾼다

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락

디자인 핸드오프의 홈(SCR-01)은 세대 카드 9장, 최근 스쿼드, 바로 가기 3개로 이루어진 대시보드이고, 앱 막대의 "홈" 탭 아래에 있다.
사용자는 홈을 **로고와 메뉴 버튼만 있는 인트로 화면**으로 만들고 싶어 한다. 옛 게임 타이틀 화면처럼 메뉴에서 도감 · 아이템 · SixSquad · 설정으로 들어가는 구조다.
디자인 시트의 "노란 선택 칸 + ▶ 커서 = 옛 메뉴의 문법"과도 맞는다.

바뀌면 흔들리는 것:
- 기준 이미지 `10_home_1440.png`가 더 이상 목표가 아니다
- 세대 선택은 핸드오프에서 홈의 주된 행동이었다. 세대는 앱 전역 상태의 중심이다
- 앱 막대에 탭이 있는데 홈에도 같은 메뉴가 있으면 탐색 경로가 둘이 된다

## 선택지

1. **인트로를 앱 막대 아래 "홈" 탭의 내용으로** — 지금 구조를 유지한다 / 탭과 메뉴가 같은 곳으로 가는 경로를 중복으로 가진다
2. **인트로를 앱 막대 없는 전체 화면으로 두고, 메뉴를 고르면 본 화면(앱 막대 + 페이지)으로 들어간다** — 타이틀 화면의 문법과 같고 경로가 중복되지 않는다 / 화면 전환이 두 단계가 된다

세대 선택 위치: 인트로에 현재 세대 버튼 / 앱 막대에서만 / 별도 세대 선택 화면

## 결정

- **선택지 2.** `MainWindow`의 central은 두 단계의 스택이다
  ```
  m_screens (QStackedWidget)
   ├ HomePage                     인트로: 로고 · 세대 버튼 · 메뉴
   └ 본 화면 (QWidget)             AppBar + m_pages (도감 · 아이템 · 스쿼드 · 설정)
  ```
- 앱 막대의 **"홈" 탭은 없앤다(탭 4개).** 마크 + 워드마크 버튼이 인트로로 돌아가는 길이다
- **세대는 인트로에 현재 세대 버튼("GEN 4 신오 ▾")으로 보여 주고 바꿀 수 있게 한다.** 앱 막대의 세대 버튼(SCR-00)도 그대로 둔다. 두 버튼은 같은 `AppState`를 본다
- 핸드오프 홈의 세대 카드 9장 · 최근 스쿼드 · 바로 가기는 Phase A에서 뺀다. 최근 스쿼드 목록은 스쿼드 화면(Phase E)에서 다시 다룬다
- 인트로 · 수정된 앱 막대 · 새 마크의 시각 기준은 Claude Design에 요청한다([요청서 0001](../../design/requests/0001-intro-and-mark.md)).
  받기 전까지는 **디자인 시트 규칙 + 가이드의 임시 와이어프레임 수치**로 진행하고, 받으면 수치만 바꾼다
- 마크 리디자인은 "더 귀엽고 둥글게, 공 · 캡슐 느낌"을 요청하되 **포켓볼의 구별 요소(위 빨강 · 아래 하양으로 나뉜 원 + 가로 띠 + 가운데 원형 버튼)는 쓰지 않는다.**
  공개 저장소의 비공식 도구가 상표 · 트레이드 드레스와 혼동될 위험이 있기 때문이다(CLAUDE.md, 핸드오프 PROMPT §5)

## 결과

- [ADR 0007](0007-ui-component-structure.md)의 원칙(그리기 함수 · 동작으로 고르는 베이스 · 겉모양을 모르는 내용 · rect = 상자 + 그림자)은 그대로 쓴다. 예시로 든 홈 컴포넌트(`GenerationCard`, `ShortcutCard`)만 인트로 컴포넌트로 바뀐다
- Phase A의 단계 구성이 바뀐다([roadmap.md](../roadmap.md)). 캡처 비교는 새 디자인이 도착한 뒤부터 한다
- 이름은 `ui/home/` · `HomePage`를 그대로 쓴다. **이 리포에서 "홈"은 인트로 화면**이고, 핸드오프 문서의 SCR-01 "홈"(대시보드)과는 다른 것이다
  (처음에는 `IntroPage`로 바꾸기로 했다가 같은 날 되돌렸다. 처음 켜면 보이고 마크로 돌아오는 화면이라 "홈"이 역할과 맞고, 바꿀 이득이 적다)
- 다시 볼 조건: 새 디자인이 인트로에 다른 정보(최근 스쿼드 이어하기 등)를 넣자고 제안할 때
