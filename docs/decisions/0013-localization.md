# 0013. 표기 언어(한국어 · 영어 · 일본어) — 게임 데이터는 DB 3열 + 대체 순서, 화면 문구는 Qt Linguist

- 상태: Accepted
- 날짜: 2026-10-01

## 맥락

아이템 목록에 영어 이름이 섞여 나왔다(특히 메일). PokéAPI에 한국어 이름이 없는 아이템이 46개였다.
그중 4세대 메일 12개와 비전머신08은 한국어판 게임에 이름이 있었고, 나머지 31개는 한국어판이 없던 3세대(RSE · FRLG) 전용이다.
또 옛 아이템 일부는 일본어 한자 표기(`ja`)는 없고 가나 표기(`ja-Hrkt`)만 있어서 일본어 칸도 비었다.
사용자는 앞으로 한국어 · 영어 · 일본어를 바꿔 가며 써도 제대로 나오기를 원한다.

화면에 나오는 글자는 출처가 둘이다.

1. **게임 데이터**: 포켓몬 · 기술 · 아이템 · 지방 · 버전 이름과 효과 문구. PokéAPI CSV에 언어별로 있다
2. **화면 문구**: 버튼 · 제목 · 안내(`tr()`). 우리가 쓴 글자다. 72개

## 결정

**게임 데이터**
- DB에 ko · en · ja 세 열을 모두 둔다(이름 · 효과 문구 · 지방 · 버전 · 기술). 효과 문구도 언어마다 따로 고른다(스키마 5)
- 일본어는 한자 표기(11)가 있으면 그것, 없으면 가나 표기(1). 전각 숫자 · 영문은 NFKC로 반각으로 바꾼다
- 한국어가 없는 아이템 중 **한국어판 게임에 이름이 있던 것만** `namesupplement.h`에 보충한다. 3세대 전용 아이템의 이름은 지어내지 않는다
- 조회 결과는 `LocalizedText { ko, en, ja }`로 들고, 화면이 `text(language)`로 고른다. 빈 언어는 대체 순서로 채운다
  - 한국어 → 영어 → 일본어 · 영어 → 한국어 → 일본어 · 일본어 → 영어 → 한국어
- 언어는 `AppState::language`(QSettings `language`)다. 바꾸면 화면이 **바로** 다시 그린다. 행에 세 언어가 다 있어서 DB를 다시 읽지 않는다
- 설정 파일(`dexstyle.json` · `itemstyle.json`)의 화면 글자는 `{ko, en, ja}`로 쓴다
- 타입 칩의 영어 · 일본어 이름은 `typechip.cpp`의 표에 둔다(세대가 바뀌어도 그대로라서)

**화면 문구**
- Qt Linguist: `translations/pokesix_en.ts` · `pokesix_ja.ts`. `qt_add_translations`가 빌드 때 `.qm`을 만들어 실행 파일 리소스(`:/i18n/`)에 넣는다
- `main.cpp`가 시작할 때 저장된 언어(또는 `--language ko|en|ja`)의 번역을 설치한다. 소스 언어가 한국어라 한국어는 번역 파일이 없다
- 실행 중에 언어를 바꾸면 화면 문구는 **다음 실행부터** 바뀐다. 위젯마다 `changeEvent(LanguageChange)`로 글자를 다시 넣어야 즉시 바뀌는데, 설정 화면이 생길 때(Phase E) 필요하면 더한다

## 결과

- 한국어로 볼 때 4세대 아이템 중 이름이 빈 것은 없다. 3세대 전용 아이템(3세대 메일 · 데봉의 짐 등)은 영어로 나온다
- 일본어 글꼴은 번들하지 않았다. 도현 · 나눔 글꼴에 가나가 없어서 OS 글꼴로 대신 그린다(Windows: Yu Gothic, macOS: Hiragino, Linux: Noto CJK 등)
- `tr()` 문구를 바꾸면 `update_translations`로 `.ts`를 갱신하고 영어 · 일본어를 채워야 한다(CLAUDE.md §5 · conventions §5)
