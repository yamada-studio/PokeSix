# 0002. core를 Qt 없는 정적 라이브러리로 분리한다

- 상태: Accepted
- 날짜: 2026-09-28

## 맥락

타입 상성, 세대별 규칙, 팀 분석은 이 앱의 핵심 로직이다. 규칙이 세대마다 달라 틀리기 쉽고,
디자인 핸드오프 04 문서는 "숫자 하나라도 다르면 규칙 구현이 틀린 것"이라는 테스트 표를 준다.
이 로직을 UI나 Qt 타입과 섞으면 테스트가 무거워지고, 규칙 버그와 UI 버그를 구분하기 어려워진다.

## 선택지

1. **core를 순수 C++로, Qt에 링크하지 않는다** — 경계가 명확하고 컴파일러가 강제한다.
   대신 레이어 경계에서 타입을 변환(`std::string` ↔ `QString`)해야 한다
2. **core가 QtCore까지는 허용한다** (디자인 설계서 03의 방식: `QList` 등) — 변환이 줄어든다.
   대신 경계가 흐려지고, "Qt를 조금만 쓰는" 코드가 점점 늘어나기 쉽다
3. **분리하지 않는다** — 초기 속도는 빠르지만 테스트하기 어렵다

## 결정

**1번.** `pokesix_core`는 Qt에 링크하지 않는 STATIC 라이브러리다. core에서 Qt 헤더를 include하면
컴파일 에러가 나므로 규칙을 문서가 아니라 빌드가 지킨다. ROS 2에서 알고리즘 라이브러리를 노드
인터페이스와 분리하는 것과 같은 발상이다.

## 결과

- core 테스트는 Qt 없이 빌드·실행된다(GoogleTest, 수 ms)
- 타입 변환은 data 레이어(repository, models)의 책임이다
- 디자인 설계서의 `AnalysisResult`(`QList`)는 `std::vector`로 바꿔 구현한다
