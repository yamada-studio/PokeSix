# 0011. 게임 데이터는 첫 실행에 PokéAPI CSV 원본(고정 커밋)을 받아 로컬 SQLite로 변환한다

- 상태: Accepted
- 날짜: 2026-09-29

## 맥락

도감 · 기술 · 습득 기술 · 아이템 데이터를 PokéAPI에서 가져오기로 했지만 방식이 열려 있었다(roadmap 열린 질문 1).
2026-09-29에 확인한 사실은 이렇다.

- **REST API**: 요청 횟수 제한은 없다. 다만 공정 이용 정책이 "받은 자원은 로컬에 캐시하라"이고, 어기면 IP 영구 차단이다.
  필요한 것을 REST로 모으면 요청이 수천 건이다. `/pokemon` 응답에 습득 기술 전체가 들어 있어서 JSON만 수백 MB가 된다(추정)
- **GraphQL**(`graphql.pokeapi.co/v1beta2`): IP당 **시간당 100회** 제한이 있다. 베타이고, 매일 01:00 UTC에 재시작하며(2분 중단), 주소가 바뀐 이력이 있다
- **CSV 원본**: PokéAPI DB의 원천은 GitHub `PokeAPI/pokeapi`의 `data/v2/csv`다(BSD-3, 187개 파일, 41.6 MB).
  필요한 파일만 고르면 **약 12 MB**이고, 그중 `pokemon_moves.csv`가 10.7 MB다. 게임 설명문(flavor text)은 빼도 된다

앱은 어느 방식을 쓰든 실행 중에는 **로컬 SQLite만 읽는다**. 세대 구간(`gen_from`/`gen_to`) 질의가 필요해서 텍스트 파일을 그대로 쓰지는 않는다.
그래서 선택지 사이의 차이는 "CSV → SQLite 변환을 누가, 언제 하느냐"뿐이다.

## 선택지

1. **첫 실행에 REST로 긁어 오기** — 리포에 데이터가 없다 / 요청 수천 건, 첫 실행 수 분, 정책 취지와 충돌한다
2. **첫 실행에 GraphQL** — 요청 수가 적다 / 시간당 100회 제한, 베타라 불안정하다
3. **개발 때 미리 변환해 앱에 동봉** — 첫 실행부터 오프라인, 가장 빠르다 / 공개 리포 · 실행 파일에 게임 데이터가 들어간다(README 정책 변경).
   데이터를 갱신하려면 앱을 다시 배포해야 한다
4. **첫 실행에 CSV 원본을 고정 커밋에서 받아 사용자 PC에서 변환** — 요청 약 20건 · 약 12 MB · 수 초, PokéAPI 서버 부하가 없다(GitHub에서 받음).
   리포에 데이터가 없고, 커밋 + SHA-256으로 재현할 수 있다 / 첫 실행에 인터넷이 필요하다. CSV 스키마에 결합된다

## 결정

**선택지 4**를 쓰고, 개발 · 테스트용 **작은 시드**를 곁들인다.

- 받는 곳: `https://raw.githubusercontent.com/PokeAPI/pokeapi/<커밋>/data/v2/csv/<파일>.csv`
  - **커밋을 고정한다.** 첫 고정값은 D4를 시작할 때 정한다(참고: 2026-09-26 master = `168b1e89467054cda2e7df43ccebbb69b459497a`)
  - 파일마다 **SHA-256을 코드에 적어 두고 검증한다.** GoogleTest를 URL + 해시로 고정한 것([ADR 0004](0004-googletest-via-fetchcontent.md))과 같은 원리다
  - 파일 목록은 D4에서 확정한다(세대 · 타입 · 상성(과거 포함) · 종 · 이름(ko/en/ja) · 포켓몬 · 타입(과거 포함) · 종족값 · 기술(변경 이력 포함) · 습득 기술 · 아이템 · 진화)
- 받은 CSV는 `CacheLocation/pokeapi-csv/<커밋>/`에 보관한다. 도중에 끊기면 **파일 단위로 이어받는다**. 디자인의 "창을 닫아도 다음에 이어서 받아요"가 이 동작이다
- 변환: `CsvImporter`가 worker 스레드에서 트랜잭션 하나로 `AppDataLocation/pokesix.sqlite`를 만든다. 완성본을 임시 파일로 만든 뒤 교체해서, 중간에 실패해도 반쪽짜리 DB가 남지 않게 한다
- 흐름을 묶는 클래스는 v2 설계서의 이름대로 `DataUpdater`다(`progress(step, total, label)` · `failed(code)` · `finished()`). 인트로의 `FirstRunPanel`이 이 신호를 받는다
- **개발 · 테스트용 시드**: 디자인 목업에 나온 4세대 19종 · 기술 · 아이템만 담은 작은 CSV를 `tests/fixtures/`에 둔다. 같은 `CsvImporter`로 변환하므로, 인터넷 없이 개발 · 테스트할 수 있고 변환기 테스트도 된다
- 설정의 "지금 갱신"은 앱이 고정한 커밋의 데이터를 다시 받는 기능이다. 새 커밋으로 올리는 일은 앱 버전을 올릴 때 한다(해시가 코드에 있으므로)

## 결과

- 리포와 실행 파일에는 게임 데이터가 없다. README의 에셋 정책을 유지한다. 데이터 출처 표기는 "PokéAPI"다
- PokéAPI API 서버에는 요청하지 않는다. `data/api`의 역할은 "HTTP 클라이언트"에서 "고정된 파일 다운로드 + 검증"으로 바뀐다
- CSV 스키마(veekun 계열)에 결합된다. 커밋을 올릴 때마다 변환기 테스트(시드 + 실제 파일 몇 줄)로 확인한다
- 선택지 3이 나중에 필요해지면(첫 실행부터 오프라인), 같은 변환기로 만든 SQLite를 **GitHub Release 첨부 파일**로 배포할 수 있다. git 리포에는 넣지 않는다
