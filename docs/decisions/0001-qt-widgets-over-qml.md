# 0001. UI는 Qt Widgets로 만든다

- 상태: Accepted
- 날짜: 2026-09-28

## 맥락

Qt 6의 UI 기술은 두 가지다. C++ 위젯 트리인 **Qt Widgets**와, 선언형 언어 QML 위의 **Qt Quick**이다.
PokeSix는 표·필터·상세 창이 많은 정보 밀도가 높은 데스크톱 도구다. 장기적으로는 에뮬레이터 오버레이도 계획하고 있다.
개발자는 C++에 익숙하고 Qt는 처음이다.

## 선택지

1. **Qt Widgets**
   - 장점: 표(`QTableView`)·트리·폼 같은 데스크톱 컨트롤이 성숙했다. 순수 C++이라 언어를 하나만 배우면 된다.
     디자인이 요구하는 각진 창, 단단한 그림자, 커스텀 페인트는 `QPainter`로 충분하다
   - 단점: 연속 애니메이션과 GPU 효과에 약하다. 스타일링은 QSS 한계를 넘으면 `paintEvent`를 직접 써야 한다
2. **Qt Quick (QML)**
   - 장점: 애니메이션, GPU 렌더링, 반응형 레이아웃이 쉽다. 오버레이 같은 반투명 창에 유리하다
   - 단점: C++와 QML 두 언어와 그 경계(프로퍼티 바인딩, `QML_ELEMENT` 등록)를 동시에 배워야 한다.
     밀도 높은 표 UI는 직접 만들어야 하는 부분이 많다

## 결정

**Qt Widgets.** 이 앱의 핵심 화면은 표와 폼이고, 디자인 핸드오프도 Widgets와 `QPainter`를 전제로
작성되었다(블러·연속 애니메이션 금지). 학습 측면에서도 C++ 하나로 Qt의 핵심(시그널/슬롯,
모델/뷰, 이벤트 루프)을 먼저 익히는 것이 낫다.

## 결과

- 모델 계층(`data/state`, `data/models`)은 QtCore만 쓴다. 그래서 나중에 QML 화면을 붙여도 그대로 재사용할 수 있다
- 에뮬레이터 오버레이 단계에서 QML(Qt Quick)을 **부분적으로** 도입할 수 있다. 그때 새 ADR로 기록한다
