# 0012. 도감 선택 버튼의 표시 규칙(버전 색 · 약칭 · 도감 숨김)은 JSON 설정 파일로 둔다

- 상태: Accepted
- 날짜: 2026-09-30

## 맥락

도감 백과의 도감 선택 버튼(D2b)은 세대마다 다르다(1세대 관동 R·G·B·Y … 7세대 알로라 S·M, US·UM).
어떤 도감이 있는지는 PokéAPI 데이터(도감 ↔ 게임 ↔ 세대)로 찾지만, **어떻게 보일지**는 데이터에 없다.

- 버전 약칭(D · P · Pt · HG · SS)과 배지 색(다이아몬드 = 연파랑 바탕에 은색 글자 …): 1–7세대만 해도 버전이 32개다
- 도감 규칙: 알로라의 섬 도감 8개는 지방 도감에 포함되므로 숨긴다. 칼로스 도감 셋(센트럴 · 코스트 · 마운틴)은 지방 이름이 같아서 이름을 바꿔야 한다

CLAUDE.md §5는 "색 · 크기는 `ui/theme` 토큰에서만"이라고 한다. `tokens.h`는 디자인 핸드오프의 토큰을 옮긴 것이고, 여기에 버전 32개를 더하면
세대를 늘리거나 색을 고칠 때마다 다시 컴파일해야 한다.

## 선택지

1. **`tokens.h`에 C++ 표로** — 컴파일 때 검사된다 / 표가 길고, 고칠 때마다 빌드해야 한다. 핸드오프 토큰과 섞인다
2. **JSON 설정 파일(qrc에 포함)** — 표를 코드와 떨어뜨려 한눈에 보고 고친다. Qt에 파서(`QJsonDocument`)가 있다 / 잘못된 값은 실행 때 알게 된다
3. **YAML** — 사람이 읽기 좋다 / Qt에 파서가 없어서 의존성이 는다
4. **SQLite에 표로 넣기** — 한 곳에서 조회 / 표시 규칙은 게임 데이터가 아니다. 데이터를 다시 변환해야 바뀐다

## 결정

2를 택한다. `resources/theme/dexstyle.json`(qrc `:/theme/dexstyle.json`)에 두고, `ui/theme/dexstyle.h`가 처음 쓸 때 한 번 읽는다.

- 위치가 `ui/theme`인 이유: 색을 정하는 곳은 여전히 theme 한 곳이다(CLAUDE.md §5의 취지). data 계층은 PokéAPI identifier만 넘긴다
- 키는 PokéAPI `versions.identifier` · `pokedexes.identifier`다. 이름(한국어 · 영어)은 바뀔 수 있어도 identifier는 안정적이다
- 파일이 없거나 깨졌으면 경고 로그만 남기고 기본 모양(영어 이름 · 흰 바탕 · 먹 글자)으로 그린다. 앱은 계속 돈다
- 같은 도감에서 약칭이 겹치면 한 번만 보인다(관동도감의 일본판 레드 · 블루)

## 결과

- 세대를 늘릴 때(8세대~)는 JSON에 버전 · 도감 규칙을 더하고 `AppState::kMaxGeneration`을 올린다. C++ 코드는 바뀌지 않는다
- 나중에 사용자 테마(다크 모드 등)를 만들 때도 같은 방식으로 파일을 바꿔 끼울 수 있다
- 잘못된 색 문자열은 컴파일 때 잡히지 않는다. 앱을 켜서 도감 버튼을 확인한다(세대 1–7을 한 번씩)
